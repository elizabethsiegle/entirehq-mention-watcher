**B. Task quality — findings**

**Critical**
1. `x-scrape.mjs:46-47` — `bb.sessions.create()` and `chromium.connectOverCDP()` run *outside* the `try/finally`. If session creation succeeds but `connectOverCDP` throws (network blip, bad `connectUrl`, CDP handshake timeout), the function throws correctly (good, matches "throw on failure") but **the just-created Browserbase session is never closed** — no code path releases it. At ~288 polls/day this leaks a running session on every connect failure; over time this exhausts Browserbase concurrency/quota. This is a real leak, not hypothetical — it needs a `try { session } catch { await bb.sessions.update/release }`.

2. `x-scrape.mjs:72` — `loginWall: false` is hardcoded on the JSON return path, discarding the `loginWall` value computed on line 69. If cookies are stale but X still serves a partial/degraded `SearchTimeline` payload before hard-walling (X permits some logged-out search), `fromJson.length` can be nonzero, so the function reports `loginWall: false` even though a wall was detected. `check.mjs` then never fires its "cookies are stale" warning on the JSON path — it prints "Looks healthy" while the session is actually dead. This directly defeats the login-wall detection the brief asks for.

**Important**
3. `x-scrape.mjs:57-67` — The response race is real and asymmetric in severity. `response.json()` is unawaited by Playwright's event dispatch; nothing tracks in-flight handler promises before `payloads` is read at line 71. The **zero-result** case is self-mitigating (falls to DOM, and `check.mjs`/brief explicitly flag `dom` + 0 tweets as suspicious). The **dangerous** case is a *partial* race: 1 of N `SearchTimeline` responses resolves before the 6s settle elapses. `fromJson.length &gt; 0` short-circuits to `source: 'json'` with no signal that data is incomplete — this looks identical to a healthy run. A caller establishing a baseline from this would seed a truncated baseline; a subsequent poll would then treat the missed tweets as "new," producing false-positive Slack notifications later. A fixed timeout with no completion signal (e.g., awaiting outstanding response promises, or requiring N consecutive empty polls before trusting `payloads`) can't distinguish "done" from "still racing."

4. `x-scrape.mjs:39` — `hasQuotedTweet` heuristic (`tweetText` count &gt; 1) will false-positive on any tweet where X renders a second `tweetText`-tagged node for reasons other than a quoted tweet — most notably the "Translate post" feature, which renders original + translated text as two separate blocks with the same test id. Result: `isQuoteStatus` mislabeled true for translated (non-quote) tweets, which `filter.mjs`'s classification downstream would then treat as a quote-kind mention incorrectly. Cannot verify against live markup (no network), so flag as a heuristic risk rather than confirmed bug.

5. `x-scrape.mjs:76-77` — `browser.close()` in `finally` is assumed to release the Browserbase session (not just the CDP socket). This is plausible for Browserbase's `connectOverCDP` flow but is exactly the kind of assumption that should be confirmed against the dashboard during the deferred live check — flagging as cannot-verify-statically, worth a follow-up check when credentials are available, since a wrong assumption leaks a session every single poll (not just on error).
