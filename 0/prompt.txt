## Findings

### Important

**1. `x-scrape.mjs:115-117` — unguarded `await browser.close()` in `finally`** (the deferred item; confirmed worse than logged). The masked-error case is the *lesser* problem. On the **success path**, `try { return {...} } finally { await browser.close() }` — a rejecting close discards the returned `{tweets}` and throws from `finally`, past the already-skipped `catch`. So: a healthy poll is logged "scrape failed", backoff escalates toward 30 min, **and `releaseSession()` never runs → a paid Browserbase session leaks**. Closing a remote CDP socket is precisely the flaky op. Wrap in try/catch; release explicitly when close throws.

**2. `watch.mjs:24, 40-47` — cookie-expiry alert is deduped in process memory only.** `loginWallAlerted` resets on every process start. `/clear` fires SessionEnd (kill) then SessionStart (respawn), as does every new session — so stale cookies post **one Slack alert per session start / per `/clear`**, not the spec's "exactly one Slack message" (spec:147). Persist the flag/timestamp in `seen.json`.

**3. Nothing alarms on any failure except a login wall.** `watch.mjs:110-114` and the `fresh.length === 0` path: a broken extractor (X changes shape/selectors → `tweets: []`) or an exhausted Browserbase quota (throw every poll) is terminal-only and indistinguishable from "nobody mentioned us." The spec calls silent failure the worst outcome for cookies; the same logic applies here and nothing implements it. Add one Slack alert (same once-only pattern) when `consecutiveFailures` reaches the 30-min cap, and when N consecutive polls scrape zero tweets after a non-empty baseline. This also removes Ruling 10's stated tell ("a suddenly-lower tracked count") from depending on a human watching the scrollback.

**4. `hook-stop.mjs:5-16` — SessionEnd kills a *shared* watcher.** Session A spawns; session B correctly no-ops on the PID file; B closes first → the watcher dies and A is left silently unwatched, with no respawn and no message. Cheapest honest fix: README + queue item; a refcount is overkill.

**5. No pagination — a hard, undocumented mention ceiling.** `x-scrape.mjs:94-96` reads one page load and never scrolls. More mentions than one page (~20 entries) inside one `X_WATCH_POLL_MS` window and the overflow is never in a payload, never in `seen`, never announced. Silent loss on exactly the busy day the tool matters.

**6. `watch.mjs` has no stdout-error or `uncaughtException` guard.** One EPIPE/EIO on the inherited fd (terminal closed; Claude Code closing the hook's stdout pipe) kills the detached process — no supervisor, no notice, and the PID file still names a dead pid so `hook-start` won't respawn until the next session. Two lines: `process.stdout.on('error', () =&gt; {})` plus an `uncaughtException` handler that logs and keeps looping.
